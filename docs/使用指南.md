# 使用指南

从下载到真发消息，按顺序走完这五步；每步都写明「成功长什么样」，卡住就看[常见问题](常见问题.md)。

## 1. 准备

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 系统 | Windows 10 / 11 | 只在 Windows 上跑（读 PC 微信消息库 + Windows UIA） |
| Python | 3.9 以上 | 3.12 实测通过。安装时勾上 *Add python.exe to PATH* |
| 微信 | PC 版 4.x，已登录 | 手机微信、网页版、企业微信都不行 |
| 权限 | 管理员 | 发送需要。不给也能跑，但退化成「坐标 + OCR」，微信窗口一动就点歪 |
| 模型 | 任一 OpenAI 兼容或 Anthropic 接口 | 含完全离机的 Ollama / LM Studio / llama.cpp / vLLM |

第三方依赖只有两个：`websockets` 和 `wechatauto-replica`（发送库，`vendor\` 里带了离线包）。

## 2. 装

双击 `scripts\install.bat`：升级 pip → 装依赖 → 跑一次体检。

在线装失败（没网、代理）时，它会直接打印一条用 `vendor\` 离线包安装的命令，复制执行即可。体检全绿再往下走。

## 3. 配 `config.yaml`

根目录的 `config.yaml` 就是全部配置。第一次运行会自动从 `config.example.yaml` 复制一份出来，然后你只用改它。

`limits` / `send` / `respond` 改完存盘就生效（按文件修改时间热重载）；`llm` / `persona` 改完要 `scripts\restart.bat` —— 除非你是在网页控制台里改，那是即时的。

### 模型

```yaml
llm:
  baseURL: "http://localhost:11434/v1"   # 模型服务地址
  api: openai                            # openai | anthropic
  model: qwen2.5:7b                      # 模型名
  apiKey: ""                             # 本地服务留空；云端填这里
```

`baseURL` 填到版本号那一层：OpenAI 兼容写 `.../v1`（代码拼 `/chat/completions`）；Anthropic 写根地址如 `https://api.anthropic.com`（代码拼 `/v1/messages`）。云端就把这两行换成服务商给的地址和模型名，例如 `https://api.deepseek.com/v1` + `deepseek-chat`。

不小心把一整条接口地址（`.../v1/chat/completions`）粘进去了也没关系，代码会把多出来那段剥掉；但剥不掉的自定义路径就得自己对 —— 测试失败时报错里会打出**实际请求的 URL**，照着它改最快。

`apiKey` 三处都能给，**谁生效**的顺序是：控制台「设置」页填过的（存 `wxbridge/brain.json`，它把地址、模型名、密钥整套盖过 `config.yaml`）> 环境变量 `WXREPLY_API_KEY`（也认 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`）> 写在这里的 `apiKey`。用本地模型（Ollama / LM Studio / llama.cpp / vLLM，地址是 `127.0.0.1`、`localhost`、`192.168.x.x` 这类）就整个留空 —— 这类服务默认不鉴权，代码不会替你编一把假密钥，没密钥也算「配好了」。

控制台那个密钥框出于安全考虑不会把已存的密钥显示出来，所以**留空提交 = 不改动**：只想换个模型名时不会顺手把密钥擦掉（密钥一旦被擦掉，云端服务就一律 401，看起来就是「连接测试失败」）。想真的抹掉：删掉 `wxbridge\brain.json`。

建议第一次先用本地模型（Ollama 之类的）把链路跑通：不用密钥、消息不出机器。换成云端后**聊天内容会发给那家服务商**，这个取舍你要清楚。

> 用带「思考」的推理模型时留意：回复大脑给模型的输出额度要留够，否则它把额度全花在思考上、正文一个字都没有，看起来就是「已读不回」。

### 说话风格

`persona` 是多行文本，原样拼进系统提示词，告诉模型「你是谁、平时怎么说话」，这里决定像不像你：

```yaml
persona: |
  你在用微信跟熟人聊天，你不是助手，也不是 AI。
  说话方式：
  - 一句话能说完就别说两句，每条不超过 20 个字。
  - 口语，不用 markdown，不用表情符号。
```

先贴三五句你和朋友的真实聊天再照着改。别在里面写账号 ID、手机号。

网页控制台「风格」页可以选预设或加补充要求，存 `wxbridge/style.json`，**它优先级高于 `persona`** —— 在控制台改过风格后，文件里的 `persona` 就被盖住了；想让文件重新说话，把风格恢复默认或删掉 `style.json`。

### 回谁

```yaml
respond:
  allowChats: [小明, 小红]   # 种子名单，只在第一次生成 allowlist.json 时起作用
  allowGroups: true          # false = 只处理私聊
  groupsNeedAt: true         # 群里只有 @ 我才回
```

真正生效的名单是 `wxbridge/allowlist.json`（第一次运行会把 `allowChats` 和你手写的 `wxbridge/allowlist.txt` 搬进去），之后以控制台「名单」页为准：

```json
[{"name": "小明", "enabled": true, "added": 1730000000}]
```

名字必须和微信里显示的会话名一模一样（好友有备注就以备注为准）。`allowGroups: false` 时群一律不回；`true` 且 `groupsNeedAt: true` 时只有 @ 你才回 —— **别把 `groupsNeedAt` 关掉**，群刷屏事故基本都是这么来的。

### 限速

```yaml
limits:
  minIntervalSeconds: 10   # 同一个人两次回复之间至少隔多久
  dailyMaxPerChat: 0       # 单人每天最多回几条，0 = 不限
  dailyMaxTotal: 0         # 全体每天最多回几条，0 = 不限
```

这三条既是防刷屏，也是风控面前最实在的护栏。样例里给 0 是为了让你先看到全貌，**头几天请改成 30 / 20 / 50**（见第 6 步）。

### 发送行为

```yaml
send:
  delaySeconds: [3, 8]     # 收到后随机隔这么久再发，像真人看了一眼才回
  maxAgeSeconds: 120       # 比这更老的消息只推水位不回
  dockRight: true          # 发送前把微信窗口摆到屏幕右半，坐标才稳
  cooloffSeconds: 30       # 连发触顶后的冷却；0 = 用发送库自带的随机冷却(30~75s)
```

`delaySeconds` 是区间，代码在中间随机取值；命令行 `--send-delay "3,8"` 可以覆盖，写 `"0"` 关掉延迟（调试用）。

`maxAgeSeconds` 防的是：电脑合盖几小时，一开盖把攒了几十条旧消息一条不漏地回一遍。

`cooloffSeconds` 改的是发送库的拟人节流参数。默认 30 秒是我自己在用的值；嫌慢也别调成 0 —— 短时间连发是风控最敏感的行为特征，觉得慢应该少回几条，而不是提高频率。

## 4. 干跑一遍，不碰微信

双击 `scripts\demo.bat`。它用假消息走完整链路（收到 → 大脑 → 拆条 → 「发送」打印到屏幕），验证模型通不通、说话像不像、拆条对不对，全程不操作微信。

只想确认配置填没填对：`scripts\doctor.bat` 会打出当前生效的模型端点是哪一个、来自 `config.yaml` 还是控制台，以及密钥状态（本地 / 局域网服务没密钥是正常，云端缺密钥它才提醒）；控制台「设置」页的「测试连接」更直接 —— 它按四个框**当前填的值**真发一条出去，不用先点保存，改成什么样就测什么。失败时它会把服务端那句英文错翻成人话（是地址填错层、还是密钥不对、还是服务压根没开），对号入座看[常见问题](常见问题.md)。

## 5. 真跑

前提：微信已登录，窗口在屏幕上看得见（别最小化、别只留托盘）。

双击 `scripts\start_admin.bat` → UAC 点「是」。脚本先体检再启动，浏览器自动打开 <http://127.0.0.1:8766/>。

控制台几页能做的事：看最近消息和「正在想」的会话、看发出去了什么和未回原因，开关名单，改说话风格，改模型和密钥，看待补发队列和日志，紧急刹车。改名单 / 风格 / 模型都是即时生效，不用重启。

读到消息的标志：首页「账号与通道」里「账号」一栏显示你的微信昵称，并且会话页开始出对方的消息。

## 6. 上线节奏：先按最小风险跑

任何自动化都存在被限制登录甚至封号的可能，这份代码不做保证。把风险压小靠的是节奏，不是运气。腾讯不公布判定规则，但可以从「机器行为长什么样」反推：单位时间操作次数异常、7×24 不停、一次发一大串、给大量陌生人发同一句话、新号高频外发、深夜密集、以及绕过客户端的协议实现。最后一条本项目在实现层面就避开了 —— 不逆向消息协议、不做协议登录，读的是本机微信自己写的消息库，发是模拟你在界面上点。这不等于安全，但风险模型和「hook 协议」不是一个档位。

建议照这个流程走：

1. 先拿小号或不常用的号跑第一周。
2. `dailyMaxTotal: 20`、`minIntervalSeconds: 30`、`allowGroups: false`，名单里只放 1~2 个熟人。
3. 头几天只让它回「在吗 / 吃啥」这类短句，观察回复质量和耗时。
4. 微信那边一有异常 —— 登录要重新验证、功能被限制、提示环境异常、发送被弹回 —— **立刻 `panic.bat` 停手**，别再试第二次，先冷却几天。
5. 参数一次只放宽一项。

内置护栏和对应配置项：

| 护栏 | 在哪 | 建议 |
| --- | --- | --- |
| 只回名单 | `respond.allowChats` → `allowlist.json` | 名单越小越好，别加同事大群、客户群 |
| 群里必须 @ | `respond.groupsNeedAt: true` | 保持默认 |
| 群处理总开关 | `respond.allowGroups: true` | 拿不准就 `false` |
| 同人最小间隔 | `limits.minIntervalSeconds: 10` | 起步 30 以上 |
| 单人 / 全局每日上限 | `limits.dailyMaxPerChat` / `dailyMaxTotal` | 起步 20 / 50，别用 0 上线 |
| 回复前随机延迟 | `send.delaySeconds: [3, 8]` | 别调成 `[0, 1]`，时间分布是特征 |
| 太老的消息不回 | `send.maxAgeSeconds: 120` | 防开盖后一次性爆发 |
| 连发强制冷却 | `send.cooloffSeconds: 30`（发送库 2 分钟窗口内写满 6 次触顶） | 别设 0 |
| 一条消息只占一次窗口 | 会话 worker 最多等 60 秒 | 宁可少回，不堆积 |
| 紧急刹车 | `Ctrl+Alt+X`、`panic.bat`、`PAUSE` 文件 | 觉得不对先刹车，别「再看一会儿」 |

千万别做：批量添加好友、拉群、群发同一句话、给别人转发营销内容、操作别人的账号、代聊骗人、多号并发注册机。这些既是封号重灾区，也可能违法，本项目不提供这些能力。

另外，让 AI 替你回**涉及金钱、承诺、隐私、工作决策**的消息，后果由你承担。这类会话建议把人从名单里摘出去，或在 `persona` 里写清「涉及钱和承诺一律回『回头当面说』」。

## 7. 三个必须知道的开关

| 想干什么 | 怎么做 |
| --- | --- |
| 立刻叫停（它在乱点界面） | 按 `Ctrl+Alt+X`，或双击 `scripts\panic.bat` |
| 恢复 | 再按一次热键 / 控制台点「恢复」 / `scripts\resume.bat` |
| 彻底关掉 | `scripts\stop.bat`（桥接和进程管家一起退） |

`stop` 一定要连管家一起退：只退桥接，几秒后管家会把它拉起来。

## 8. 密钥、隐私与本机数据

所有服务只绑 `127.0.0.1`，不对本机以外的网络开放；8766 / 8767 的写接口有 Origin 校验，浏览器来的请求必须出自本机页面。

三处都能放密钥（谁生效见第 3 步：控制台 `brain.json` > 环境变量 > `config.yaml`）。论稳妥则反过来：环境变量 > 控制台里填 > 明文写在 `config.yaml`。三者归根到底都是明文落在磁盘上，多用户电脑上有泄露面；`config.yaml` 和 `wxbridge/brain.json` 都在 `.gitignore` 里不会被提交，但你自己别把它们打包发给别人 —— 提 Issue 前先看[开发说明](开发说明.md)里的「别提交什么」。

除了你填的那个模型端点，代码没有任何远程调用。读消息要解密本机微信数据库（`wechatauto-replica` 的做法，密钥从本机微信进程取），解密结果和本程序产生的缓存都落在你用户目录和 `wxbridge/` 下，别把它们共享或备份到不信任的位置。

运行时会写出来的文件（都在 `wxbridge/` 下，全部 `.gitignore` 排除）：

| 文件 | 内容 |
| --- | --- |
| `allowlist.json` / `allowlist.txt` | 名单（txt 是给人手写的镜像） |
| `style.json` | 控制台改过的说话风格 |
| `brain.json` | 控制台改过的模型地址/密钥 |
| `recent.jsonl` | 最近消息缓存，重启后控制台不清空 |
| `pending.jsonl` | 待补发队列（发送失败、被刹车拦下的先进这里） |
| `PAUSE` | 存在 = 紧急刹车踩着，一条都不发 |
| `bridge.out.log` / `supervisor.out.log` / `panic.log` | 日志 |
| `supervisor.state` / `*.pid` | 进程管家状态与意图标记 |
| `wechatauto_logs/` | 发送库自己的日志 |

发送库的节流计数落在**当前用户目录**的 `rhythm.json`（跨进程共享），所以「冷却中」这个状态重启也不会清零 —— 这是故意的。

## 9. 不用 YAML 库也能跑

`wxbridge/appconfig.py` 自带一个只支持这份配置子集的解析器（缩进 + `key: value` + 块标量 + 流式列表），不依赖 PyYAML；装了 PyYAML 会自动优先用它，行为一致。别在 `config.yaml` 里玩锚点、多文档。
