# 开发说明

这份文档讲三件事：代码怎么搭的（架构）、外面怎么调它（接口）、想改代码怎么开始（规范与坑）。只用不改的话读[使用指南](使用指南.md)就够了。

## 一、架构

### 三个进程

| 进程 | 文件 | 端口 | 职责 |
| --- | --- | --- | --- |
| 桥接 | `wxbridge/bridge.py` | 8765（WebSocket）/ 8766（控制台） | 全部业务逻辑 |
| 进程管家 | `wxbridge/supervisor.py` | 8767 | 拉起/重启桥接、开微信、看门狗、紧急刹车热键 |
| 刹车热键 | `wxbridge/panic_hotkey.py` | — | 常驻监听 `Ctrl+Alt+X`，桥接卡死也能刹 |

平时你只需要跑 `ctl.py start`：它先脱离式启动管家，管家再把桥接拉起来并盯着 —— 桥接崩了自动重启。`ctl.py stop` 会停桥接并顺手退掉管家，否则几秒后管家又把桥接拉起来。

全部只绑 `127.0.0.1`，不接受外部连接；8766 / 8767 的写接口有 Origin 校验 —— 浏览器里的请求必须来自本机页面，命令行工具（没有 Origin）放行。

### 消息从进来到发出去

```
后端轮询（backends/wechatauto.py 读本地消息库）
   │  InboundMessage：会话、发送人、内容、是否 @ 我、时间戳
   ▼
Bridge._on_inbound → _enqueue → 每个会话一个 worker（_chat_worker）
   │   ├ 一个会话一个工人；这一轮里同一会话攒下的多条消息合并成一条再给大脑
   │   ├ _skip_reason：不在名单 / 群未 @ 我 / 消息太老(maxAgeSeconds) / 自己发的 / 空内容
   │   ├ _count_ok：minIntervalSeconds、dailyMaxPerChat、dailyMaxTotal
   ▼
选谁来回
   │   RESPONDER = "brain"（默认）：桥接自己调 brain.py
   │   RESPONDER = "client"：推给连在 8765 上的外部应答端；它不在才回落本地大脑
   ▼
brain.py
   │   系统提示词 = persona（或控制台 style 覆盖）+ 该会话最近 8 条历史
   │   → 调你的模型（openai / anthropic 两种报文，max_tokens 8000）
   │   → _clean 去 markdown / 引号 / 前缀，banned_words 兜底
   │   → split_at_punct 最多拆 2 条（只认中英文逗号句号问号，避免切坏网址和小数）
   ▼
发送：随机延迟 delaySeconds → 看 PAUSE → 后端 UIA 操作界面
   ▼
结果落 recent.jsonl / pending.jsonl（失败进待补发队列，控制台可手动补发）
```

`RESPONDER` 是 `bridge.py` 顶部常量，默认 `brain` —— 整套东西不依赖任何外部程序。

### 「正在想」和几道保险丝

回复要等模型，控制台得知道现在是在想还是卡了：收到消息时标记 `_thinking`，`/api/status` 就把这个会话显示成「正在想」。挂了外部应答端（`RESPONDER = "client"`）时还有 `_think_guard` 兜着：应答端接了活却超过 `THINK_RESCUE_SECONDS` 没动静（它重启、断网、卡死），本地大脑立刻把这句接回去，不会一直转圈不回。`_reaper` 则清掉那些连上却不报身份的旧连接。

冷却期不会无限等：一条消息最多等 60 秒（`_wait_for_slot`），等不到就跳过这一条并记进「最近异常」—— 宁可少回一条，也不要越攒越多然后一次性爆发。

发送失败按原因分流：紧急刹车 / 锁屏 / 微信无响应 / 发送超时进待补发队列（界面缓过来自动补，补发前回读消息库查重，防同一条发两遍），会话名找不到则直接放弃并提示名字要对得上。

### 模块职责

| 文件 | 干什么 |
| --- | --- |
| `appconfig.py` | 读 `config.yaml`（自带无依赖解析器），按 mtime 热重载 |

| `web_dashboard.py` | 8766 控制台（`web/index.html` 单文件）+ 热配置读取 |
| `supervisor.py` | 进程管家：拉起/看护桥接、开微信、状态查询 |
| `ctl.py` | 一键入口，也是 bat 背后唯一的命令实现 |
| `winproc.py` | 进程枚举、管理员判断等 Win32 小工具 |
| `backends/base.py` | `Backend` 抽象 + `InboundMessage` |
| `backends/wechatauto.py` | 正式后端：读库 + UIA 发送 + 拟人节流 |
| `backends/mock.py` | 联调后端：脚本喂消息，打印发送，不碰微信 |
| `tools/` | 手动补发(`send_once.py`)、送达核验(`check_sent.py`)、消息定位(`who_said.py`) |

### 后端为什么这么设计

读消息走的是**本地微信消息库**（`wechatauto-replica` 解密），不是界面文字识别，所以天然覆盖所有会话、也不会漏群消息；发送走 **UIA 界面操作**。读写分家是刻意的：读可以一直轮询，写必须慢。

发送前有硬性节流：库自带的拟人节奏（`rhythm`）在 2 分钟窗口内写满 6 次就强制冷却，冷却秒数由 `send.cooloffSeconds` 决定（默认 30）。计数存在用户目录 `rhythm.json`，跨进程、跨重启共享。

UIA 树要能起来，需要往 `Weixin.dll` 写一个激活字节 —— 这就要管理员权限。非管理员时后端退化成「坐标 + OCR」找按钮，微信窗口位置一变就点歪，这是 Windows 权限模型的边界，不是能优雅绕过的东西。所以推荐 `start_admin.bat`。

### 状态与恢复

进程管家把「你希望它在跑」记在 `supervisor.state`；桥接重启后 `_mark_lost_on_start` 会把上次没结论的回复标记为丢失，不去重复轰炸。`recent.jsonl` 让控制台重启后还看得到最近在聊什么。`PAUSE` 文件存在时，所有发送点一步都不做，但读和记录继续 —— 你能看着它憋着不发。

## 二、接口

### WebSocket 通道 · 8765

`ws://127.0.0.1:8765`，一行一条 JSON（UTF-8，不转义中文）。

默认配置下没有外部应答端也能跑 —— 桥接自己就是回复方。你把 `bridge.py` 里的 `RESPONDER` 改成 `"client"`，才把消息交给连上来的应答端处理；应答端没接上或这一轮失败时，本地大脑照样会顶上（`--brain off` 可以关掉这个兜底）。

服务端 → 客户端：

```jsonc
{"op":"hello","account":"你的微信昵称","backend":"wechatauto","protocol":1}

// 收到一条别人的消息
{"op":"message","chat":"会话名","chatType":"group","sender":"张三",
 "text":"在吗","mentioned":true,"ts":1730000000000}

{"op":"sent","chat":"会话名","ok":true}     // 发送结果回执
{"op":"error","chat":"会话名","ok":false,"message":"发送失败"}
{"op":"pong"}                                // 对 ping 的回应
```

`chatType` 是 `group` 或私聊；`mentioned` 表示这条有没有 @ 你。`chat` 一律用微信里显示的会话名（好友用备注名），发送时就靠它在搜索框里定位。

客户端 → 服务端：

```jsonc
{"op":"identify","version":"1.0.0","pid":1234}   // 连上后第一帧，自报身份
{"op":"send","chat":"会话名","text":"回复内容"}
{"op":"thinking","chat":"会话名"}                // 我已经交给模型了，控制台不再显示「没动静」
{"op":"skip","chat":"会话名","text":"原消息","reason":"不在名单"}   // 主动说这条不回
{"op":"failed","chat":"会话名","reason":"模型超时"}                // 这轮挂了 → 本地大脑立刻顶上
{"op":"ping"}
```

`identify` 之后 15 秒内没收到（`IDENTIFY_TIMEOUT`）也不会被当僵尸杀掉 —— 旧版应答端不认识这个帧，链路得兼容。但如果已经有报过身份的客户端在，60 秒不说话的哑巴连接会被 `_reaper` 关掉。

接一个自定义应答端的最小实现：

```python
import asyncio, json, websockets

async def main():
    async with websockets.connect("ws://127.0.0.1:8765") as ws:
        await ws.send(json.dumps({"op": "identify", "version": "my-1.0", "pid": 0},
                                 ensure_ascii=False))
        async for raw in ws:
            frame = json.loads(raw)
            if frame.get("op") != "message":
                continue
            print(frame["chat"], frame["text"])
            await ws.send(json.dumps({"op": "send", "chat": frame["chat"],
                                      "text": "收到"}, ensure_ascii=False))

asyncio.run(main())
```

联调时把桥接换成假后端，不用碰微信：

```
python -X utf8 wxbridge\bridge.py --backend mock --demo --port 9765
```

### 控制台 HTTP · 8766

页面在 `/`（`wxbridge/web/index.html`，单文件、无外部 CDN）。GET：

| 路径 | 返回 |
| --- | --- |
| `/api/status` | 主状态：最近消息、正在想谁、未回原因、账号、名单。带 `?since=<上次rev>&wait=20` 是长轮询，有新内容立刻返回 |
| `/api/health` | 五项健康检查：微信 / 读消息 / 名单 / 大脑 / 发送，每项带结论和补救提示 |
| `/api/allowlist` | `{"entries":[…],"names":[…]}` |
| `/api/style` | 说话风格快照（预设 + 自定义） |
| `/api/brain` | 模型端点快照（密钥只回「有没有」，不回明文） |
| `/api/pending` | 待补发队列 `{"items":[…],"count":n,"paused":bool}` |
| `/api/events` | 最近异常（从通道日志里挑出有意义的行） |
| `/api/logs?tail=80` | 通道日志尾部 |

POST，请求体都是 JSON：

| 路径 | 体 | 作用 |
| --- | --- | --- |
| `/api/allowlist` | `{"add":["小王"],"remove":["小红"],"toggle":{"name":"小王","enabled":false}}` | 改名单，即时生效 |
| `/api/style` | `{"preset":"casual","custom":"少用问号"}` 或 `{"text":"…全量风格文本"}` | 改说话风格 |
| `/api/style/preview` | `{"message":"在吗","text":"可选风格"}` | 拿这条风格现生成一句看看，不发送 |
| `/api/brain` | `{"api":"openai","baseURL":"…","model":"…","apiKey":"…"}` | 改模型，写 `brain.json`；`apiKey` 空串 = 沿用已存的，不是清空 |
| `/api/brain/test` | `{"api":"openai","baseURL":"…","model":"…","apiKey":"…"}`（可整个省略） | 用**这组参数**（空着的沿用已存/配置文件里的值）真打一条：返回 `ok` / `error`（翻译成人话）/ `reply` / `elapsed` / `info.url` |
| `/api/pause` | `{"on":true}` / `{"on":false}` | 踩 / 松刹车（等价于 `PAUSE` 文件） |
| `/api/pending/flush` | `{}` | 立刻排空待补发队列 |
| `/api/pending/clear` | `{}` | 清空队列，不发 |
| `/api/reply` | `{"chat":"小王","text":"帮他生成一条回复"}` | 只生成不发送，用来试风格 |
| `/api/send` | `{"chat":"小王","text":"…"}` | 直接发一条（真人发出去，用来手动补话） |

例子：

```bash
curl -s -X POST http://127.0.0.1:8766/api/allowlist \
  -H 'content-type: application/json' \
  -H 'Origin: http://127.0.0.1:8766' \
  --data '{"add":["小王"]}'
```

### 进程管家 HTTP · 8767

`GET /api/control/status`：

```json
{"ok":true,
 "bridge":{"running":true,"pids":[4321],"port":8765,"wanted":true},
 "dashboard":{"running":true,"port":8766},
 "wechat":{"running":true,"pids":[9182]},
 "admin":false,
 "port":8767}
```

`wanted` 是「你希望它在跑」的意图标记，重启电脑后管家据此决定要不要再拉起来。

`POST /api/control/<动作>`：

| 动作 | 作用 |
| --- | --- |
| `bridge/start` | 拉起桥接（已在跑则返回 `already`） |
| `bridge/stop` | 停桥接（同时清掉 `wanted`，免得看门狗又拉起来） |
| `bridge/restart` | 重启桥接，让要重启的配置生效 |
| `wechat/open` | 启动本机微信客户端 |

```bash
curl -s -X POST http://127.0.0.1:8767/api/control/bridge/restart -H 'content-type: application/json' -d '{}'
```

非管理员时 `bridge/start` 会附带一条 `warning`：发送会退化成坐标 + OCR，建议改用 `scripts\start_admin.bat`。

### 命令行 · ctl.py

`python -X utf8 wxbridge\ctl.py <命令>`，`--help` 看全部。命令名和 `scripts\*.bat` 一一对应：`doctor` / `start` / `stop` / `restart` / `status` / `console` / `panic`（`panic --resume` 松开）/ `demo`。

`doctor` 检查：Python 版本、四个依赖、模型端点（按大脑那套优先级：控制台 `brain.json` 填齐了就用它，否则 `config.yaml`，并把用的来源标出来）、密钥（本地 / 局域网地址没密钥算正常，云端缺密钥才提示）、人设、名单、是否管理员、微信在不在跑、三个端口占没占。

### 代码风格与结构约束

Ruff，`line-length = 110`，目标 Python 3.9（`pyproject.toml` 里配好，装了 ruff 直接 `ruff check .`）。中文注释和中文日志是刻意的 —— 使用者是中文用户，报错看得懂才有用。`%` 格式和 f-string 都行，注意 f-string 表达式里不能有反斜杠（要兼容 3.9）。

`wxbridge/appconfig.py` **不能引入第三方依赖**：自带 YAML 子集解析器是有意的，让用户少装一个包。

后端都实现 `backends/base.py` 的 `Backend` 抽象：必须给出 `start(sink)`（收到消息后调 `sink(InboundMessage)`）、`stop()`、`send(chat, text)`；`account()` 返回当前登录昵称。两个可选覆盖：`can_send_now()`（暂停 / 锁屏 / 微信无响应时告诉上层别硬发）、`already_delivered(chat, text, since)`（补发前回读消息库查重，防同一条发两遍）。加新后端就在 `backends/` 下新建文件，并在 `bridge.py` 的 `--backend` 选项里注册。

`bridge.py` 默认不依赖任何外部程序 —— 请保持这一点：新增功能若必须引入外部服务，要做成可关掉的（参考 `RESPONDER = "brain" / "client"` 那种回落）。

改行为时同步改文档：`README.md` 和 `docs/` 下三份（使用指南 / 常见问题 / 开发说明）。

### 模型端点这四处约定，改动前先看

`brain.py` 里跟「用户自己接的模型」有关的行为有四条刻意设计，每一条都对着一种「连接测试失败」的报法，改之前先确认你要怎么绕过它：

`_url_of(ep)` 负责把 `baseURL` 拼成真地址。用户会照服务商文档整条粘进来（`…/v1/chat/completions`），所以它**先剥尾部重复段再拼**：OpenAI 兼容剥掉 `/chat/completions`、`/completions`，路径里已经有 `/v数字`（`/v1`、`/compatible-mode/v1`、`/v1beta/openai`）就不再补 `/v1`；Anthropic 剥 `/messages` 和 `/v1` 后拼 `/v1/messages`。别改成无脑 `base + "/chat/completions"`，那只会得到 404。

`_is_local_server(base)` 判定 `localhost` / `127.*` / `10.*` / `192.168.*` / `172.16-31.*` / `::1` / `*.local` / `host.docker.internal`。用途只有一个：本地和局域网的推理服务默认不鉴权，`available()` 在这时**不要求密钥**，`_endpoint()` 也不给它编一把 `"local"` 之类的假密钥发出去（编了反而让严格校验的服务 401）。云端地址仍然必须有密钥，缺了健康检查会直接报「模型没配好」并说明缺的是哪一项。

`brain_store.save(..., apiKey="")` 是「不改动」。控制台出于安全从不回显已存密钥，所以用户改模型名时提交的必然是空串，按空串写盘等于把密钥擦掉。真要抹掉走 `clear_key=True`（目前只有测试和手动删 `brain.json` 这条路）。

`Brain.probe(api, baseURL, model, apiKey)` 是「测试连接」的实现：把这四个框的当前值临时塞进 `self._probe`，`_endpoint()` 优先读它，所以**没保存也能测**；测完 `finally` 里清掉 `_probe` 并把 `__probe__` 这条虚拟会话从历史里 pop 走 —— 它不落盘、不污染真实会话上下文。报错一律过 `_friendly_error()` 翻成中文（404 会说清地址填到哪一层并附上真正请求的 URL），别把原始 exception 直接抛给页面。

### 一键脚本是生成的

`scripts\*.bat` 不是手写的，由 `scripts\make_bats.py` 生成，输出 GBK + CRLF —— cmd 按代码页解码，UTF-8 的 bat 会把中文注释读成乱码甚至报语法错误。改 bat 就改生成器再重跑：

```
python -X utf8 scripts\make_bats.py
```

`ctl.py` 里加子命令时，顺手在 `make_bats.py` 里加对应 bat，两边保持一致。

### 别提交什么

提 PR 前 `git status` 看一眼，这些必须被忽略，也别手动附加上去：

`config.yaml`、`wxbridge/allowlist.json`、`wxbridge/allowlist.txt`、`wxbridge/style.json`、`wxbridge/brain.json`、`wxbridge/recent.jsonl`、`wxbridge/pending.jsonl`、`wxbridge/PAUSE`、`wxbridge/*.log`、`wxbridge/wechatauto_logs/`、`vendor/` 里你自己放的其他包。

它们里面有**真实联系人名字、聊天内容、模型密钥**。仓库里所有样例数据都是编的（小明、小红、小王、`wxid_self00000001`）—— 请保持这样，贴日志到 Issue 前先打码。

### 已知的坑，别再踩

`import wechatauto` 会**动 stdout**：一是丢掉还没刷新的缓冲（重定向输出时，import 之前 `print` 的内容整段消失，所以所有打印都要 `flush=True`），二是把 `sys.stdout` 换成它自己的 UTF-8 流（cmd 的 936 代码页下，从那以后的中文全成乱码）。`ctl.py` 的对策是在任何重量级 import 之前把启动时的流存成 `_CONSOLE_OUT`，所有输出显式写回它 —— 新增打印请照这个来，别直接 `print` 到 `sys.stdout`。

发送库的节流计数存在**当前用户目录**的 `rhythm.json`，跨进程共享。改冷却用 `rhythm.configure(cooloff=(x, x))`，不要去改库内部逻辑；冷却秒数已经由 `send.cooloffSeconds` 驱动。

UIA 树需要管理员权限（要往 `Weixin.dll` 写一个激活字节）。非管理员的退化路径是坐标 + OCR，不稳定，不要把它当等价方案来测。

同一时间只能有一套桥接占 8765；两套会双发。
